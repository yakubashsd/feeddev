# ListingFlow — запуск продаж

Этот документ — операционный сценарий первого платного клиента. Он дополняет `SELECTEL_DEPLOY.md` и `LEGAL_LAUNCH_CHECKLIST.md`.

## 1. Что уже готово в продукте

- регистрация с отдельным принятием оферты и согласия на обработку персональных данных;
- изоляция проектов клиентов, роли владельца и менеджера;
- тариф 5 000 ₽ за проект на 30 дней, лимит 1–10 проектов;
- Platega checkout, проверка callback по `X-MerchantId` и `X-Secret`, идемпотентная активация;
- история и журнал платежей, повторная оплата после неуспешного заказа;
- восстановление пароля через SMTP и ограничение частоты чувствительных запросов;
- архив проектов без отключения опубликованных ссылок, версии выпусков и откат;
- семидневный read-only период после окончания тарифа;
- мониторинг, email/Telegram-уведомления, техподдержка;
- экспорт данных аккаунта и формализованный запрос на удаление;
- зашифрованное файловое хранилище и резервное копирование.

## 2. Внешние действия до открытия регистрации

Эти пункты нельзя безопасно выполнить только изменением кода:

1. Указать полный юридический адрес и телефон, проверить реквизиты по актуальной выписке ЕГРИП.
2. Проверить необходимость уведомления Роскомнадзора и подать его до начала обработки данных, если требуется.
3. Согласовать с бухгалтером налоговый режим, предмет расчёта и ставку НДС/«без НДС».
4. Получить у Platega письменное подтверждение схемы формирования чеков либо подключить отдельную онлайн-кассу. Platega API создаёт платёж и сообщает его статус, но публичная документация не описывает передачу фискального чека.
5. Провести тестовую оплату, callback, чек, возврат/оспаривание и сверку суммы.
6. Проверить SMTP на реальном адресе и выполнить пробное восстановление из резервной копии.
7. Передать оферту, политику и согласие профильному юристу на финальную проверку.

До выполнения пункта 4 оставьте `BILLING_MODE=manual` и `ONLINE_RECEIPTS_READY=false`. После подтверждения установите `BILLING_MODE=platega` и `ONLINE_RECEIPTS_READY=true`.

## 3. Проверка конфигурации

На сервере из каталога приложения выполните:

```bash
npm run check:launch
```

Команда завершается с кодом `1`, пока остаются блокеры. Значения секретов не выводятся. Тот же итог доступен в `GET /api/health` через поля `launchReady`, `launchBlockers` и `launchWarnings`.

Обязательные значения перечислены в `.env.example`. Секреты сгенерируйте независимо друг от друга, например через `openssl rand -base64 48`.

## 4. Platega

В кабинете Platega задайте callback:

```text
https://ВАШ-ДОМЕН/api/billing/platega/callback
```

Callback должен быть публичным HTTPS URL с доверенным сертификатом. По документации Platega уведомления повторяются при отсутствии успешного ответа, поэтому обработка в ListingFlow идемпотентна.

Проверьте четыре сценария:

1. `PENDING` после создания заказа отображается в истории клиента.
2. `CONFIRMED` активирует подписку ровно один раз и на правильное число проектов.
3. Повторный `CONFIRMED` не продлевает подписку повторно.
4. `CANCELED` и `CHARGEBACKED` отражаются в клиентской истории и админке.

## 5. Контрольный путь первого клиента

1. Открыть сервис в чистом профиле браузера и выбрать cookies.
2. Зарегистрировать новый аккаунт, принять документы, выйти и войти снова.
3. Проверить восстановление пароля из письма.
4. Оплатить один проект либо активировать счёт вручную.
5. Создать проект, загрузить тестовый XML, исправить блокирующие ошибки и опубликовать ссылку.
6. Открыть ссылку в отдельном браузере и проверить XML без авторизации.
7. Перезапустить сервис и убедиться, что проект и ссылка сохранились.
8. Создать обращение в поддержку и увидеть его в админке.
9. Скачать копию данных аккаунта.
10. Запустить `npm run backup`, восстановить снимок в отдельный тестовый `DATA_DIR` и повторить вход.

## 6. Решение об открытии продаж

Продажи можно открывать, когда одновременно выполнены условия:

- `npm test` и `npm run check` проходят;
- `npm run check:launch` сообщает о готовности;
- `/api/health` отдаёт `launchReady: true`;
- тестовый платёж, чек и возврат подтверждены;
- свежий backup восстановлен на тестовом каталоге;
- юридические документы проверены и совпадают с фактическими процессами.
