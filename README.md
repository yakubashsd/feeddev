# ListingFlow

Сервис для загрузки, редактирования, проверки и публикации XML-фидов недвижимости для агрегаторов.

## Что уже умеет MVP

- Загружать фид по ссылке или XML-файлом.
- Определять площадку фида: ЦИАН, Авито, Яндекс Недвижимость, Домклик.
- Редактировать объекты точечно и массово.
- Показывать ошибки фида и подсказки по исправлению.
- Скачивать обновленный XML.
- Давать фиду пользовательское название перед публикацией.
- Сохранять обновленный XML на сервере и отдавать его по постоянной ссылке вида `/f/feed-id.php`.

## Быстрый запуск локально

```bash
npm start
```

После запуска откройте:

```text
http://localhost:3000
```

Проверка сервера:

```text
http://localhost:3000/api/health
```

## Как работает генерация ссылки

1. Пользователь вставляет ссылку на исходный XML-фид или загружает XML-файл вручную.
2. Если это ссылка, сервер подтягивает XML по этой ссылке, чтобы не упираться в браузерные ограничения CORS.
3. Если это файл, сервис разбирает XML локально в интерфейсе.
4. Пользователь редактирует объекты в рабочей области.
5. В блоке `Финальная выгрузка` пользователь задает название фида.
6. Пользователь выбирает результат:
   - `Скачать XML` - получить файл без публикации на сервере.
   - `Получить ссылку` - сохранить XML на сервере и получить постоянный адрес.
7. Сервис сохраняет обновленный XML в папку `data/feeds`.
8. Пользователь получает постоянную ссылку:

```text
https://ваш-домен.ru/f/название-фида.php
```

Эту ссылку можно передавать агрегатору. При повторной генерации сервис обновляет XML по той же ссылке.

## API

### Загрузить внешний фид через сервер

```http
POST /api/feeds/import
Content-Type: application/json

{
  "url": "https://example.ru/feed.xml"
}
```

### Опубликовать новый фид

```http
POST /api/feeds
Content-Type: application/json

{
  "platform": "cian",
  "sourceUrl": "https://example.ru/feed.xml",
  "sourceType": "url",
  "name": "Символ ЦИАН июль",
  "objectCount": 120,
  "xml": "<?xml version=\"1.0\"?><feed></feed>"
}
```

### Обновить опубликованный фид

```http
PUT /api/feeds/{feed-id}
Content-Type: application/json

{
  "platform": "cian",
  "sourceUrl": "https://example.ru/feed.xml",
  "sourceType": "file",
  "name": "Символ ЦИАН июль",
  "objectCount": 120,
  "xml": "<?xml version=\"1.0\"?><feed></feed>"
}
```

### Получить XML по постоянной ссылке

```http
GET /f/{feed-id}.php
```

## Настройка на сервере

Для публикации в интернете нужен VPS или PaaS-хостинг с Node.js 18+.

Минимальные переменные окружения:

```bash
PORT=3000
PUBLIC_BASE_URL=https://feeds.your-domain.ru
```

`PUBLIC_BASE_URL` нужен, чтобы сервис генерировал внешние ссылки сразу с вашим доменом.

## Развертывание на Selectel

Продакшен-контур запускается как постоянно работающий Node.js-сервис на Selectel. Данные, XML-фиды и резервные копии хранятся в каталоге `DATA_DIR`. Полная последовательность настройки описана в `SELECTEL_DEPLOY.md`.

## Доступ по логину и паролю

Добавьте переменные окружения в конфигурацию сервиса Selectel:

```text
AUTH_USERNAME=ваш_логин
AUTH_PASSWORD=ваш_пароль
AUTH_SECRET=длинная_случайная_строка
```

После изменения переменных перезапустите сервис. `AUTH_SECRET` используется только для подписи защищенной сессионной cookie и не показывается пользователю.

## Отдельный контур для внешних пользователей

Внешний SaaS запускается отдельным деплоем из ветки `codex/saas-admin`. Корпоративный деплой оставьте в режиме `APP_MODE=internal`: его логин, проекты и данные не смешиваются с клиентскими. Основной SaaS-контур рассчитан на постоянно работающий сервер Selectel; инструкция находится в `SELECTEL_DEPLOY.md`.

Для внешнего деплоя задайте:

```text
APP_MODE=external
SAAS_SESSION_SECRET=длинный_случайный_секрет_для_cookie
SAAS_DATA_SECRET=отдельный_секрет_шифрования_данных
EXTERNAL_ADMIN_EMAIL=admin@example.ru
EXTERNAL_ADMIN_PASSWORD=надежный_пароль
FREEKASSA_MERCHANT_ID=идентификатор_магазина
FREEKASSA_SECRET_1=секретное_слово_1
FREEKASSA_SECRET_2=секретное_слово_2
PUBLIC_BASE_URL=https://app.example.ru
DATA_DIR=/var/lib/feeddev-saas
```

Тариф рассчитывается по количеству активных проектов: 7 500 ₽ за проект на 30 дней, от 1 до 10 проектов в аккаунте. Регистрация создаёт аккаунт без доступа, успешное уведомление FreeKassa активирует или продлевает подписку и устанавливает оплаченный лимит проектов. Владелец входит обычной формой с `EXTERNAL_ADMIN_EMAIL` и открывает `/admin.html`, где видит клиентов, проекты, платежи, сроки, лимиты и динамику выручки. В разделе «Команда» владелец может создавать менеджеров.

В кабинете FreeKassa укажите URL уведомлений:

```text
https://app.example.ru/api/billing/freekassa/callback
```

Success URL и Fail URL можно направить на корень внешнего приложения. Секреты FreeKassa используются только на сервере. Уведомление проверяется по секретному слову №2, а доступ выдаётся идемпотентно — повторный callback не продлевает подписку второй раз.

Аккаунты и платежи сохраняются в отдельном AES-256-GCM хранилище. На Selectel используется `${DATA_DIR}/saas-store.enc`, а рабочие черновики проектов шифруются по отдельности в `${DATA_DIR}/project-state`. Записи публикуются атомарной заменой файла и сериализуются внутри процесса. Для нескольких экземпляров приложения это хранилище следует заменить транзакционной БД, сохранив интерфейсы `saas-store.js` и `project-state-store.js`.

## Уведомления в Telegram и по email

### Подключение Telegram из проекта

В мониторинге нажмите «Подключить Telegram», откройте бота по выданной ссылке,
нажмите Start и вернитесь в сервис. Проверьте имя найденного аккаунта и нажмите
«Подтвердить получателя». Ссылка одноразовая, действует 10 минут; до подтверждения
уведомления этому аккаунту не отправляются. «Отключить» удаляет привязку проекта.
Ранее введённые вручную Chat ID необходимо подключить заново этим способом.

Токен бота хранится только в `TELEGRAM_BOT_TOKEN` на сервере. Используйте новый
токен после отзыва ранее раскрытого. Сервер получает сообщения через getUpdates:
запускайте один процесс бота, без одновременно работающего webhook или второго
polling-процесса. На Selectel он работает внутри постоянно запущенного Node.js-сервиса.
Привязки и позиция обработки сохраняются в `data/telegram-links.json`.

Текущий сервис использует одну общую учётную запись. Привязки разделены по этой
учётной записи и ID проекта; независимые клиенты требуют отдельных аккаунтов
и серверной проверки прав на проекты перед внешним запуском.

Чтобы мониторинг отправлял сообщение при новой ошибке фида, добавьте в окружение Selectel:

```text
TELEGRAM_BOT_TOKEN=токен_бота_из_BotFather
```

Создайте бота через `@BotFather`, добавьте новый токен в окружение постоянно работающего Node-сервера и перезапустите процесс. Подключите личный Telegram-аккаунт через кнопку проекта. Ручной Chat ID для уведомлений больше не используется.

Для отправки email добавьте параметры SMTP-провайдера:

```text
SMTP_HOST=smtp.example.ru
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=notifications@example.ru
SMTP_PASS=пароль_или_пароль_приложения
EMAIL_FROM=ListingFlow <notifications@example.ru>
```

В разделе «Мониторинг» каналы включаются для всего проекта, там же задаётся email и подключается подтверждённый Telegram-аккаунт. Сервер проверяет фиды раз в 12 часов и сообщает о новых или изменившихся ошибках доступности и синтаксиса XML. Это не заменяет полную проверку полей площадки в редакторе.
