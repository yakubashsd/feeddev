# FeedDev

Сервис для загрузки, редактирования, проверки и публикации XML-фидов недвижимости для агрегаторов.

## Что уже умеет MVP

- Загружать фид по ссылке или XML-файлом.
- Определять площадку фида: ЦИАН, Авито, Яндекс Недвижимость, Домклик.
- Редактировать объекты точечно и массово.
- Показывать ошибки фида и подсказки по исправлению.
- Скачивать обновленный XML.
- Давать фиду пользовательское название перед публикацией.
- Сохранять обновленный XML на сервере и отдавать его по постоянной ссылке вида `/f/feed-id.php`.

## Быстрый запуск локально

```bash
npm start
```

После запуска откройте:

```text
http://localhost:3000
```

Проверка сервера:

```text
http://localhost:3000/api/health
```

## Как работает генерация ссылки

1. Пользователь вставляет ссылку на исходный XML-фид или загружает XML-файл вручную.
2. Если это ссылка, сервер подтягивает XML по этой ссылке, чтобы не упираться в браузерные ограничения CORS.
3. Если это файл, сервис разбирает XML локально в интерфейсе.
4. Пользователь редактирует объекты в рабочей области.
5. В блоке `Финальная выгрузка` пользователь задает название фида.
6. Пользователь выбирает результат:
   - `Скачать XML` - получить файл без публикации на сервере.
   - `Получить ссылку` - сохранить XML на сервере и получить постоянный адрес.
7. Сервис сохраняет обновленный XML в папку `data/feeds`.
8. Пользователь получает постоянную ссылку:

```text
https://ваш-домен.ru/f/название-фида.php
```

Эту ссылку можно передавать агрегатору. При повторной генерации сервис обновляет XML по той же ссылке.

## API

### Загрузить внешний фид через сервер

```http
POST /api/feeds/import
Content-Type: application/json

{
  "url": "https://example.ru/feed.xml"
}
```

### Опубликовать новый фид

```http
POST /api/feeds
Content-Type: application/json

{
  "platform": "cian",
  "sourceUrl": "https://example.ru/feed.xml",
  "sourceType": "url",
  "name": "Символ ЦИАН июль",
  "objectCount": 120,
  "xml": "<?xml version=\"1.0\"?><feed></feed>"
}
```

### Обновить опубликованный фид

```http
PUT /api/feeds/{feed-id}
Content-Type: application/json

{
  "platform": "cian",
  "sourceUrl": "https://example.ru/feed.xml",
  "sourceType": "file",
  "name": "Символ ЦИАН июль",
  "objectCount": 120,
  "xml": "<?xml version=\"1.0\"?><feed></feed>"
}
```

### Получить XML по постоянной ссылке

```http
GET /f/{feed-id}.php
```

## Настройка на сервере

Для публикации в интернете нужен VPS или PaaS-хостинг с Node.js 18+.

Минимальные переменные окружения:

```bash
PORT=3000
PUBLIC_BASE_URL=https://feeds.your-domain.ru
```

`PUBLIC_BASE_URL` нужен, чтобы сервис генерировал внешние ссылки сразу с вашим доменом.

## Развертывание на Vercel

1. Импортируйте репозиторий в Vercel и оставьте Framework Preset в значении `Other`.
2. В разделе Storage создайте публичное хранилище Blob и подключите его к проекту. Vercel автоматически добавит переменную `BLOB_READ_WRITE_TOKEN`.
3. Запустите новый Deploy. Главная страница откроется по корневому адресу проекта.

На Vercel XML-файлы и сведения о сохраненных фидах записываются в Blob. При локальном запуске сервис продолжает использовать папку `data`.

## Доступ по логину и паролю

Добавьте в Vercel в разделе `Settings` → `Environment Variables`:

```text
AUTH_USERNAME=ваш_логин
AUTH_PASSWORD=ваш_пароль
AUTH_SECRET=длинная_случайная_строка
```

Переменные должны быть доступны в окружении Production. После добавления выполните Redeploy. `AUTH_SECRET` используется только для подписи защищенной сессионной cookie и не показывается пользователю.

## Уведомления в Telegram и по email

Чтобы мониторинг отправлял сообщение при новой ошибке фида, добавьте в Vercel:

```text
TELEGRAM_BOT_TOKEN=токен_бота_из_BotFather
TELEGRAM_CHAT_ID=id_чата_или_канала
```

Создайте бота через `@BotFather`, добавьте его в нужный чат или канал и дайте право писать сообщения. `TELEGRAM_CHAT_ID` можно получить через `getUpdates` после первого сообщения боту или через служебных Telegram-ботов для определения ID. После добавления переменных выполните Redeploy.

Для отправки email добавьте параметры SMTP-провайдера:

```text
SMTP_HOST=smtp.example.ru
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=notifications@example.ru
SMTP_PASS=пароль_или_пароль_приложения
EMAIL_FROM=FeedDev <notifications@example.ru>
```

В разделе «Мониторинг» каналы включаются для всего проекта, там же задаются email и при необходимости отдельный ID Telegram-чата. Если ID чата в проекте пуст, используется `TELEGRAM_CHAT_ID` с сервера. Сервер проверяет все фиды проекта раз в 12 часов. Сообщение с названием проекта и проблемного фида отправляется только при новой ошибке или изменении текста ошибки, чтобы не дублировать одинаковые уведомления.

## Что добавить перед подписочной моделью

- Авторизацию пользователей.
- Привязку фидов к аккаунту пользователя.
- Базу данных вместо локальной папки `data`.
- Очередь фоновой проверки фидов по расписанию.
- Web push для уведомлений об ошибках.
- Ограничения тарифов: количество фидов, частота проверок, размер XML.
- Логи публикаций и история версий фида.
